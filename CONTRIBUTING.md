# Contributing

Keep the original scope in `docs/ORIGINAL_BRIEF.md`. Make behavior changes in a
development revision, not during a frozen campaign. Never replace failed evidence
with a later successful attempt. Reference controls and model repairs must remain
clearly distinguishable.

Run the portable tests shown in the README. Fixture changes also require Linux
boundary and behavioral checks. Use exact candidate allowlists, bounded execution,
explicit cost reservations and secret-free artifacts. Every patch is for human
review; never promote a generated repair automatically.

The initial Git history imports previously completed work in coherent feature
commits. Those commits are created at import time, not backdated development history.
